## Bug ที่พบและแก้แล้ว

1. **[ความปลอดภัย/เงิน] คนทั่วไปขอราคาสมาชิกเองได้** — `apps/catalog/services/pricing_service.py:68` (`resolve_tier`) เดิมรับ `membership_level` จากข้อมูลที่ส่งมาก่อนเสมอ ใครก็ส่ง `membership_level=platinum` หรือ `partner` ไปที่ `/booking/quote/` แล้วจองได้ราคาถูกลง และลูกค้าใหม่ถูกสร้างเป็นระดับนั้นด้วย (ระบบเดิม Next.js/DRF ก็มีปัญหานี้) แก้: ให้เลือกระดับได้เฉพาะพนักงานหน้าร้าน ลูกค้า/คนทั่วไปใช้ระดับในข้อมูลลูกค้าของตัวเอง (`quote(..., allow_tier_override=...)` บรรทัด 88) — หน้าเว็บจองไม่ได้ส่งค่านี้อยู่แล้ว หน้าตา/ราคาปกติไม่เปลี่ยน
2. **[ความปลอดภัย] Admin ทั่วไปยึดบัญชี superuser ได้** — `apps/accounts/services/user_service.py:19` หน้า Users แก้ได้ทุกบัญชี รวม superuser (ตั้งรหัสผ่านใหม่แล้วเข้า `/django-admin/` ได้) และบัญชีลูกค้า (เปลี่ยนเป็น admin ได้) แก้: แก้ได้เฉพาะบัญชีพนักงาน, superuser แก้ได้โดย superuser เท่านั้น, ห้ามปิดใช้งาน/ลดตำแหน่งบัญชีตัวเอง (บรรทัด 58) — view ส่ง `actor` ที่ `apps/backoffice/views/admin_pages.py:138`
3. **ปุ่ม "พิมพ์ใบปะหน้า" ใช้ได้ครั้งเดียว** — `static/js/app.js:114` `TL.busy()` เก็บข้อความปุ่มไว้ใน `data-label` ซึ่งชนกับ `data-label="{{ job.pk }}"` ของหน้า Operations (`templates/backoffice/operations.html:56`) กดครั้งที่สองจะเรียก URL ที่มี HTML แทนเลขงาน แก้: `TL.busy` ใช้ key ของตัวเอง (`data-tl-busy-label`) — ไม่เปลี่ยนหน้าตา (ทดสอบด้วย Node แล้ว)
4. **กดสร้าง Walk-in ซ้ำหลังผ่านไป 1 นาทีแล้ว error** — `apps/inspections/services/walkin_service.py:21` เวลาของรายการถูกคิดใหม่ทุกครั้ง ทำให้ fingerprint เปลี่ยน การส่งซ้ำ (เน็ตหลุดแล้วกดอีกที) ได้ข้อความ "รหัสรายการนี้บันทึกข้อมูลชุดอื่นแล้ว" แทนที่จะได้รายการเดิม แก้: ถ้ามีรายการของ `request_key` นี้แล้ว ใช้วันเวลาเดิม
5. **แก้ Walk-in ใส่เบอร์ที่เป็นของลูกค้าคนอื่น → HTTP 500** — `apps/inspections/services/walkin_service.py:74` เบอร์โทรเป็น unique แก้: ตรวจก่อนและแจ้งข้อความภาษาไทย
6. **Promo Code** — `apps/catalog/services/promo_service.py:104` แก้ไขโค้ดแบบเปอร์เซ็นต์โดยส่งแค่ค่าส่วนลดข้ามการตรวจ "ไม่เกิน 100%" ได้ และ `usage_limit` เป็น 0/ติดลบได้ แก้: ตรวจค่าที่จะบันทึกจริง

อื่น ๆ (ไม่ใช่ bug ของระบบ): `config/settings/test.py` ให้ test เขียนไฟล์ลงโฟลเดอร์ชั่วคราวแทน `./media` และบังคับปิด LINE/WeChat ระหว่าง test; ปรับ test เดิม 1 ตัวใน `apps/core/tests.py` ให้ระบุว่าเป็นพนักงานเลือกระดับ

## คำถามถึงเจ้าของระบบ

1. **ข้อ 1 ที่แก้ไป (ราคาสมาชิก)**: ยืนยันว่าลูกค้าออนไลน์ต้องได้ราคาตามระดับในระบบเท่านั้น ไม่ให้เลือกระดับเอง ใช่ไหม (ระบบเดิมเปิดช่องนี้ไว้ น่าจะไม่ตั้งใจ)
2. **ยกเลิกรายการที่แนบสลิปแล้วแต่ยังไม่อนุมัติ** (`apps/bookings/services/cancellation_service.py:38`): ตอนนี้ยกเลิกทันทีและบันทึกว่า "ไม่ต้องคืนเงิน" ทั้งที่ลูกค้าอาจโอนเงินมาแล้ว (เหมือนระบบเดิม) ต้องการให้เป็น "รอตรวจคืนเงิน" แทนหรือไม่
3. **ยกเลิกรายการที่จ่ายด้วยเครดิตสมาชิก**: ตอนนี้คืนเงินเป็นการโอนนอกระบบ (บันทึกเลขอ้างอิง) ไม่ได้คืนเข้ากระเป๋าเครดิตอัตโนมัติ ต้องการคืนเข้าเครดิตหรือไม่
4. **เปลี่ยนเลขใบรับรอง**: ตอนนี้พนักงานทุกตำแหน่ง (รวม front) เปลี่ยนได้ ควรจำกัดเฉพาะ admin/expert หรือไม่
5. **อนุมัติคำขอยกเลิก/คืนเงิน**: ตอนนี้ front desk อนุมัติได้ (เหมือนระบบเดิม) แต่ข้อความบอกว่า "รอ Admin ตรวจสอบยอดคืนเงิน" ควรจำกัดเฉพาะ admin/manager หรือไม่
6. **หลังเพิกถอนใบรับรอง** ต้องการให้ผู้เชี่ยวชาญแก้ผลตรวจและออกใบใหม่ได้หรือไม่ (ดูข้อ 6 ด้านบน)
